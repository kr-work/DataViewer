## 2026-10-29 — メタデータの保存先とバージョン管理
- `Project` の情報は `project.json` に、Experiment 以下は `metadata.sqlite` に保存する。
  1 フォルダ 1 プロジェクトなので DB に project テーブルは持たない。
- バージョンは 2 つを独立に管理する。
  - `project.json` の `format_version`（`PROJECT_FORMAT_VERSION`）
  - `metadata.sqlite` の `PRAGMA user_version`（スキーマバージョン）
- 開くときは `project.json` のバージョンを先に確認し、モデル検証の前に新しすぎる形式を拒否する
  （未知フィールドを拒否する設定のため、そのまま検証すると原因が分かりにくいエラーになる）。
- マイグレーション方針:
  1. `_MIGRATIONS[i]` がバージョン i → i+1 の SQL。追加のみ行い、既存の要素は書き換えない。
  2. 各マイグレーションは 1 トランザクションで実行し、失敗時は ROLLBACK して元のバージョンのまま例外にする。
  3. 既存データのある DB を移行する前に `metadata.sqlite.v{N}.bak` を作る（既存のバックアップは上書きしない）。
  4. アプリより新しいバージョンの DB・project.json は開かない。
- 代替案: Alembic などのマイグレーションツール → v0.1 の規模では依存とファイル数の増加に見合わない。

## 2026-10-29 — SQLite スキーマの表現と制約
- 列名はモデルのフィールド名と一致させ、入れ子のモデル・リスト・辞書は JSON 文字列で保存する。
  一致はテストで検査する。
- 名前の一意性: Experiment 名はプロジェクト内で一意。Session・Trial・Source・Channel 名は親ごとに一意。
  ツリー表示や凡例で区別できなくなるのを防ぐための仮定で、不要なら制約を外すマイグレーションを追加する。
- Event の基準 Source は同じ Trial に属することを、複合外部キーで保証する。
- `original_relpath`・`dataset_relpath` はプロジェクト内で一意。

## 2026-10-29 — 時間軸と単位
- Event の時刻は、必ずいずれかの Source の時間軸で定義する（`source_id` 必須）。Trial 共通の時間軸は持たない。
- `TimeAxisKind` は生データ用の 3 種類（サンプル番号・相対秒・絶対時刻）だけにする。
  イベント相対時刻は整列後の表示軸であり、生データの時間軸と混同しないよう含めない
  （整列機能の Phase で別の型として定義する）。当初は 4 種類を定義して型で除外していたが、
  typing.Literal を使わない方針に合わせて簡素化した。
- 時刻列がない Source の時間軸はサンプル番号とする。
- `Channel.unit` は None を「単位不明」、"1" を「無次元」として区別する。

## 2026-10-29 — パスの扱い
- メタデータ内のパスは、プロジェクトルートからの POSIX 形式（"/" 区切り）の相対パスだけを保存する。
  ".."・絶対パス・バックスラッシュ・空要素を拒否する。
- 相対パスを実パスへ解決するときは、シンボリックリンクを辿った実体がプロジェクト外を指さないことも確認する。
- プロジェクトを開くとき、空のサブディレクトリが欠けていれば作り直す（Git・ZIP で失われやすいため）。
  一方 `metadata.sqlite` が欠けている場合は、データ消失を隠さないよう空の DB を作らずにエラーにする。

## 2026-10-29 — 合成データの設計
- センサ非依存の汎用データにする（上記「目的の明確化」）。真値が解析的に分かる 1 次元の運動
  （正弦波の和）を、周波数・時刻原点・時刻の単位が異なる 2 ファイルで観測する。
  - `high_rate.csv`（既定 1000 Hz、時刻は秒）: 加速度の観測値。バイアス・白色ノイズ・高周波振動を含む。
    フィルタ・積分の確認用。
  - `low_rate.csv`（既定 100 Hz、時刻はミリ秒の整数）: 位置の観測値。白色ノイズを含む。カルマンフィルタの確認用。
- 真値列（`true_` 接頭辞）を同じファイルに入れる。処理結果と真値を同じ画面で重ねて比較できるようにするため。
  解析の入力には観測列だけを使う。
- 異常の割り当て: 試技 index % 3 が 1 なら高レート側の行欠落、2 なら低レート側の NaN。
  加えて `broken/` に失敗データ 7 種（空・ヘッダーのみ・列名重複・cp932・NaN/空欄・時刻逆転・時刻重複）を置く。
- 生成器は `scripts/` ではなくパッケージ内（`synthetic.py`）に置き、`ewb-synthetic` コマンドで実行する。
  テストから import するためで、薄い中継スクリプトは作らない。
- 既定の規模は SPEC §10 に合わせて 180 秒・3 試技。テストでは 1〜3 秒に縮める。
- EKF・AKF 用の非線形観測や雑音特性の変化を含むデータは、カルマンフィルタ系の仕様が決まった時点で追加する。

## 2026-10-29 — コーディング規約（ユーザー指示）
- `model.py` には pydantic モデルと、そのフィールド型の列挙型・定数だけを置く。
  検証処理や既定値の生成は `validation.py` の関数にし、モデルの検証メソッドからは呼び出すだけにする。
- `typing` モジュール（`Annotated`・`Literal`・`Final`・`Self`・`Any`・`Protocol` など）は使わない。
  `numpy.typing` も同様に避ける（指示の範囲が未確認のため、避ける側に倒した）。代替:
  - 制約付きフィールド: `Field(ge=..., le=..., pattern=...)`、複雑な検証は `field_validator` から validation.py を呼ぶ
  - 選択肢: `Literal` ではなく StrEnum、または `Field(ge, le)` の整数
  - 自身の型: `"ClassName"` の文字列注釈。インターフェース: `abc.ABC`
  - NumPy 配列: validation.py の `FloatArray = np.ndarray[tuple[int, ...], np.dtype[np.float64]]`
  - NumPy / SciPy の型定義がリテラルを要求する引数（`edge_order`・`padtype`）は、分岐して直接渡す
- 影響: 型の表現力は少し下がるが、mypy strict は通る。pydantic の型（`PositiveFloat` など）は使う。

## 2026-10-29 — Phase 1: 解析コアの設計
- 構成: `analysis/signal_processing.py`（入力検証・フィルタ・微分・積分）と
  `analysis/kalman.py`（KF・EKF・AKF）の 2 ファイル。処理条件のモデルは `model.py` に置き、
  v0.2 の処理ノードでそのまま保存・再適用できるようにする。
- 入出力: 処理クラスは `apply(t, x)` で時刻 [s] と値を受け取り、新しい配列を返す（入力は変更しない）。
  時刻の単位換算（ミリ秒 → 秒など）は呼び出し側で明示的に行う。
- 入力異常の扱い（SPEC 原則 6「隠して修正しない」）:
  - 時刻の逆行・重複・非有限値、値の NaN・無限大はエラー（位置と個数を示す）。補間・除去はしない。
  - 等間隔を前提とする処理（バターワース・移動平均・Savitzky-Golay）は、間隔のばらつきが中央値の 5% を
    超えたらエラー。ジッタは許しつつ、1 サンプル以上の欠損は必ず検出するための値。処理ごとに変更できる。
  - 不等間隔に対応する処理（中心差分・積分・運動学モデルの KF）は、そのまま計算する。
- フィルタ:
  - バターワースは SOS 形式（数値的に安定）。ゼロ位相は `sosfiltfilt`、因果的は `sosfilt`（初期状態 0）。
    端点の延長方法（padtype）を条件として記録する。
  - 移動平均の端点（窓が揃わない部分）は NaN にする。折り返しなどで補うと存在しない値を使うため。
- カルマンフィルタ:
  - **自前実装（NumPy）にし、filterpy は開発用依存としてテストの答え合わせだけに使う**。
    理由: filterpy 2.0 には適応推定（R の推定）がなく、EKF の予測は線形の F を前提としていて
    非線形の状態遷移には上書きが必要。時刻間隔ごとの F・Q の計算や、時刻ごとの記録（R・更新の有無）も
    自前で書く必要がある。さらに matplotlib への依存があり、型情報もない。
    KF の式自体は短く、filterpy の結果との一致（相対誤差 1e-9）をテストで確認している。
  - 線形 KF と EKF は同じ更新ループで扱う（線形モデルでは EKF の式が KF と一致する）。
    共分散の更新は Joseph 形式。先頭時刻は予測せず、初期状態を事前推定として更新のみ行う。
  - 観測に NaN を含む時刻は欠測として予測のみ行い、`updated=False` を記録する（多次元観測の部分更新は未対応）。
  - EKF の非線形モデルは Python の関数で与える API のみ。関数は保存できないため、
    パイプラインに保存して再適用するには、組み込みモデルの登録の仕組みが別途必要（v0.2 以降で検討）。
  - AKF は観測雑音共分散 R の推定のみ（窓付きイノベーション推定と Sage-Husa 推定）。Q の適応は
    発散しやすいため今回は対象外。推定した R は固有値を下限で抑えて正定値にし、その時刻を記録する。
- 依存: SciPy を実行時依存に追加。開発用に scipy-stubs（SciPy の型情報）と filterpy を追加。
  パッケージに `py.typed` を置き、利用側でも型検査できるようにした。

## 2026-10-29 — 入出力関係・周波数解析と、GUI 上で見て調整する流れ（ユーザー要望）
- 要望:
  - 張力が出たときの電圧の時間的な応答・遅れを調べたい。ヒステリシスも分かるとよい。
  - 加速度データなどの周波数解析（FFT・ウェーブレット・スペクトル解析）をしたい。
  - 縦並べ比較は必要な要件。今後の解析は GUI 上で見て判断して調整する流れにしたい。
    カルマンフィルタの行列なども、GUI 上で数値を簡単に変更できることが前提。
- SPEC への反映: 解析コア A-09〜A-14、GUI の F-10〜F-13、完了条件（§12）、決定待ちの論点（§13）、
  フェーズの変更案（§11）。パネルの論点は「縦に並べた複数パネル主体」で確定した。
- 設計への影響:
  - **GUI での条件編集**: 解析条件はすべて pydantic モデルなので、GUI の入力欄はモデルから組み立て、
    検証エラー（validation.py の日本語メッセージ）をそのまま表示できる。行列（F・H・Q・R・P0）は表で編集し、
    LinearSystemParams / KalmanInitialState で検証してから適用する。
  - **GUI での EKF**: EKF の非線形モデルは Python の関数で与えるため、そのままでは GUI から編集できない。
    任意 Python 実行を v0.1 に含めない方針（SPEC §9）と両立させるため、名前と数値パラメータで選べる
    組み込みモデルの仕組みを用意する。どのモデルを用意するかは §13 の決定待ち。
  - **再計算の速さ**: 現行のカルマンフィルタ（Python のループ）の実測値は下表のとおり。
    1 kHz × 180 秒を全区間で計算し直すと数秒かかるため、「数値を変えてすぐ見る」には対策が要る。
    再計算をワーカースレッドで行い、進捗表示とキャンセルを付けることは必須とする（SPEC §8 の方針どおり）。
    そのうえで、調整中は表示範囲だけで試算して確定時に全区間を計算する案と、ループの高速化
    （新しい依存が必要になるため、実測で必要と分かった場合のみ）を Phase 3 で比較して決める。

    | データ | KF | 適応 KF | バターワース |
    |---|---|---|---|
    | 100 Hz × 180 秒（18,000 サンプル） | 0.35 秒 | 0.44 秒 | 1.1 ミリ秒 |
    | 1000 Hz × 180 秒（180,000 サンプル） | 3.0 秒 | 4.3 秒 | 6.3 ミリ秒 |

    （Windows 11 の開発機で計測。等速度モデル、適応 KF は窓長 100 の窓付きイノベーション推定）
  - **異なるファイルの縦並べ**: 同じ Source の列はそのまま同じ時間軸に並べる。異なる Source は、
    同じ時計で記録したこと（またはオフセット）が明示されている場合だけ時間軸を連動させる（SPEC 原則 5）。
    Phase 2 では「同じ時計で記録した」ことの明示だけを入れ、補間（リサンプリング）は
    サンプルごとの対応が必要な解析（X-Y 表示・相互相関など）のために Phase 4 で入れる。
  - **入出力関係の解析**: 2 チャンネルのサンプルが同じ時刻に対応していることが前提。
    立ち上がりの検出（しきい値）とヒステリシスの分岐判定（入力の変化方向・平滑化）の条件は、
    結果と一緒に記録する。しきい値による立ち上がり検出は、v0.2 のイベント自動検出でも再利用できる形にする。
  - **周波数解析のライブラリ**: FFT・Welch 法・短時間フーリエ変換・クロススペクトル・コヒーレンスは SciPy
    （`scipy.fft`、`scipy.signal.welch`・`ShortTimeFFT`・`csd`・`coherence`）を使う。連続ウェーブレット変換は
    SciPy から削除済み（1.15 で削除、インストール済みの 1.18.1 にもないことを確認）のため、PyWavelets を
    周波数解析の Phase で依存に追加する。PyWavelets 1.8.0 が NumPy 2.5.4 で動き、複素モルレーの変換で
    50 Hz の正弦波を正しく検出できることを確認済み。窓関数・区間長などの条件と、ウェーブレットの影響円錐
    （端点の影響を受ける範囲）は結果に含め、表示でも隠さない。等間隔の時刻が必要（A-01 の検査を使う）。
  - **GUI の表示の種類**: 縦並べの時系列に加えて、X-Y 表示・スペクトル（対数軸）・時間周波数の画像
    （時間軸を縦並べと連動）が必要になる。Phase 2 のパネル設計は、これらを後から追加できる形にする。
- 決定（同日ユーザー承認）: Phase 2 以降の順序は「GUI の土台（Phase 2・3）を先に作り、入出力関係（Phase 4）と
  周波数解析（Phase 5）を後から載せる」。理由は、GUI で見て調整する流れが今後の解析すべての前提であり、
  既存の解析コア（フィルタ・カルマンフィルタ）だけでもその流れを試せるため。
  代替案は「解析コアの拡張（A-09〜A-14）を先に作ってから GUI に進む」。GUI なしでテストできる利点がある一方、
  結果を目で確かめられない期間が長くなる。

## 2026-10-29 — Phase 2: 取り込みと縦並べ表示の設計
- **時刻の同期の明示**: 取り込み時に「同じ試技の他のファイルと同じ時計・同じ原点で記録した」ことを
  チェックで明示し、`TimeBase.shares_trial_clock` に記録する。時刻を比較できるのは、同じ Source の列どうしと、
  同じ試技でどちらも同期済みの Source どうしだけ（`timebase.time_domain_key`）。既定は「独立した時計」。
  同じ試技の中に、互いには同期していない同期済みの組が 2 つある場合は表せない。必要になったら
  「時計グループ」に拡張する（Phase 4 の時刻オフセットによる対応付けと合わせて検討）。
- **縦並べの連動**: 1 つのパネルには時刻を比較できるチャンネルだけを置ける（置けない理由を表示する）。
  基準パネル（上から見て最初にデータを置いたパネル）と時刻を比較できるパネル、および空のパネルは時間軸を
  連動させる。比較できないパネルは連動させずに警告を表示し、自分のデータ全体が見えるよう自動調整に戻す。
  PyQtGraph の連動は、縦軸の目盛り幅の差を補正して同じ時刻が画面上の同じ横位置に来るように合わせる。
- **取り込みの異常の分類**:
  - エラー（取り込まない）: 空のファイル、ヘッダーのみ、列名の重複、文字コードの誤り、指定した列がない、
    数値として読めない値、時刻列の欠損。
  - 警告（取り込んで Source.issues に記録する）: 値の NaN・空欄、時刻の逆行・重複、時刻の飛び
    （間隔が中央値の 1.5 倍超）、空行。逆行・重複があっても並べ替えず、ファイルの順のまま保存する。
  - Polars は列名の重複を黙って改名し、文字コードの誤りを置換文字で読み進めるため、読み込む前に
    標準ライブラリでヘッダーと文字コードを検査する。
  - 数値の前後の空白（"1.0, 2.0" のような書き方）は書式の違いとして無視する。列名は書かれたまま保持する。
  - 空行は値を含まないので取り除き、件数と位置を警告として記録する。報告する行番号はファイル上の
    データ行の番号（表示は 1 始まり）。UTF-8 の BOM は文字コードの印なので取り除いて読む。
- **元ファイルの扱い**: 元ファイルは一度だけ読み込み、そのバイト列で検証・コピー・ハッシュ計算をすべて行う
  （途中でファイルが変わっても、検証した内容とコピーが食い違わない）。コピーは書き込み後に読み直して
  SHA-256 が一致することを確かめる。元ファイルには書き込まない。
- **正規化データ**: `datasets/<Source ID>.parquet`。秒に換算した時刻の列 `__time_s`（float64）と、
  各チャンネル（float64、欠損は null のまま）。元ファイルのコピーは `originals/<Source ID>/<元のファイル名>`。
  どちらも上書きせず、取り込みに失敗したら削除する。時刻列の予約名は当初 `time_s` にしたが、実データの
  列名と衝突して「時刻列ではない time_s 列」を取り込めなくなるため `__time_s` に変えた。
- **時刻列の形式**: Phase 2 では数値の時刻列（秒・ミリ秒・マイクロ秒・ナノ秒、相対または UNIX 時刻）に対応する。
  日時の文字列（"2026-10-29 12:00:00" など）は「数値として読めない」エラーとして説明し、対応は実測 CSV の
  形式（SPEC §13）が分かってから決める。時刻列がない場合は、利用者が指定したサンプル間隔とサンプル番号から
  時刻を作る（`TimeBase.sample_interval_s` に記録）。UNIX 時刻を秒の float64 で保存すると分解能は
  約 0.2 µs になる（表示・解析には十分と判断）。
- **DB スキーマ v2**: Source に読み込み条件（read_options）と取り込み時の異常（issues）を追加した
  （初めての実際のマイグレーション。v1 の行は read_options が None、issues が空になる）。
- **スレッド**: ファイルの検証・コピー・正規化（`DataImporter.prepare`）はワーカースレッド、DB の操作
  （登録先の解決と登録）はメインスレッドで行う。SQLite の接続はスレッドをまたいで使えないため。
  登録先の新しい実験などは、登録の確定時にまとめて登録する（失敗時に空の実験が残らないように）。
- **表示**: PyQtGraph の表示用間引き（ピーク保存型）を使い、時刻が単調増加のデータだけ表示範囲の切り出しを
  使う。欠損（NaN）の区間は線をつながない。カーソルの値は補間せず、最も近いサンプルの時刻と値を表示する。
- **表示の保存**: `views/main.json`（Phase 2 では 1 つ）。プロジェクトを閉じるとき・画面を閉じるときに自動で
  保存し、開いたときに復元する。保存されていたチャンネルが見つからない場合は、表示から外してメッセージで知らせる。
- **GUI の実装方針**: pyqtgraph には型情報がないため、pyqtgraph のクラスは継承せずに部品として使う。
  カーソルの属性名は QWidget の `cursor()` メソッドと衝突しないよう `cursor_line` にした。
  Qt のコンボボックスは列挙値を文字列として保持するため、取り出すときに列挙型へ変換する
  （当初これを怠り、TSV・Parquet を選んでも CSV として扱う不具合があった。テストで検出して修正済み）。
  メニューの操作は、テストからも呼べる公開メソッド（`create_project`・`open_project`・`start_import` など）にした。
- **依存**: PySide6-Essentials（PySide6 全体は Web エンジンなど不要な大型モジュールを含むため）、PyQtGraph、
  開発用に pytest-qt。GUI のテストは画面を出さない offscreen モードで実行する。CI の Ubuntu では
  Qt が使うシステムライブラリを apt で入れる（CI と Ubuntu 実機での動作は未確認）。
- **性能の実測**（Windows 11 の開発機、180 秒 × 1 kHz の合成データ 8.7 MB・約 18 万行）:
  プレビュー 0.03 秒、取り込み 0.09 秒、1 チャンネルの読み込み 9 ミリ秒。

## 2026-10-29 — Phase 3: GUI 上での解析と調整の設計
- **保存できる解析（`AnalysisSpec`）**: 1 つの入力チャンネルに 1 つの処理をかける単位。種類（`AnalysisKind`）と、
  その種類の条件だけを持つ。他の種類の条件も入っていればエラーにする（保存した内容から、実際に使った条件を
  読み違えないため）。カルマンフィルタの条件は `KalmanSettings`（モデルの種類・初期状態・適応推定）で、
  モデルの条件も同じ規則。保存先は `pipelines/<解析 ID>.json`。複数段の処理と複数試技への一括適用は v0.2。
- **出力の ID**: 解析 ID と出力名から UUID5 で決める。再計算・再起動しても同じ ID になるので、表示設定
  （views/）から解析の出力を参照できる。解析の種類を変えたら新しい解析 ID にする。出力の構成が変わる
  （フィルタは 1 系列、カルマンフィルタは状態ごと）ため、同じ ID のままだと前の種類の出力が更新されずに残る。
  入力チャンネルを選び直したときも新しい解析にする。
- **出力の内容**:
  - フィルタ・微分・積分は 1 系列。単位は微分が「/s」、積分が「·s」を付けたもの。
  - カルマンフィルタは、状態ごとの推定値（±√P の帯、観測更新しなかった時刻に × 印）、イノベーション
    （±√S の帯）、観測雑音の標準偏差 √R。多項式の観測モデルと線形モデルの状態の単位は「不明」にする
    （推定する x は観測と単位が違い、行列の状態の意味も分からないため、勝手に付けない）。
- **計算結果のキャッシュ**: `derived/<解析 ID>/<指紋>.parquet`。指紋は、入力チャンネル・種類・条件の JSON の
  SHA-256 の先頭 16 文字（名前・ID・作成日時は結果に影響しないので含めない）。正規化データは変更しないので、
  同じ指紋なら同じ結果として使う。条件が変わったら古いキャッシュを消す。開き直したときは、キャッシュを読み、
  なければ（読めなければ）計算し直して保存する。キャッシュは生データと条件から再現できる派生データ。
- **EKF の組み込みモデル（仮定。ユーザーに確認待ち、SPEC §13）**: 「運動学モデル + 多項式の観測」
  （z = c0 + c1·x + c2·x² + …）を用意した。センサの出力（電圧など）が、推定したい物理量（張力など）の
  既知の非線形関数で表される場面を想定している。任意の Python を実行しない方針（SPEC §9）のまま、数値だけで
  保存・編集でき、多くの校正曲線を近似できるため。代替案は、指数・対数・べき乗の観測関数や、状態遷移も
  非線形なモデル（減衰振動など）。どれが必要かを確認してから追加する。
- **実行と中止**:
  - 解析はワーカースレッド（QThreadPool）で実行する。DB には触れず、入力データはメインスレッドで読んで渡す。
  - カルマンフィルタは 2000 ステップごとに進捗の関数を呼び、中止の合図があれば `AnalysisCancelledError` で止める。
  - 新しい実行を始めると前の実行に中止を指示し、世代番号で古い結果を捨てる。中止を確認しない処理
    （フィルタなど）の結果も、届いた時点で古ければ表示しない。画面を閉じるときは中止して最大 5 秒待つ。
  - 自動再計算は、条件を変えるたびに最後の変更から 400 ms 待って実行する（数値を打っている途中で
    毎回計算しないため）。オフにして「実行」で計算することもできる。
- **カルマンフィルタの高速化（Phase 2 で「Phase 3 で決める」とした件）**:
  - 新しい依存は増やさず、ループ内の計算を減らした。
    運動学モデルの F・Q を時間幅ごとに覚えて使い回す（不等間隔で増え続けないよう上限 256 個、共有する配列は
    読み取り専用）。観測が 1 次元のときはゲインを割り算で求める。欠測の判定をループの前にまとめる。
  - 実測（1 kHz × 180 秒）: KF は 3.0 秒から 2.3 秒、適応 KF は 4.3 秒から 3.6 秒になった。数秒の計算は
    進捗表示と中止で対応する。
  - 「表示範囲だけで試算する」案は採らなかった。カルマンフィルタの結果は先頭からの履歴に依存するので、
    表示範囲の途中から計算すると結果が変わり、見て調整した結果と確定後の結果が食い違うため。
  - さらに速さが必要になったら numba などを検討する（新しい依存なので、実測で必要と分かってから）。
- **GUI の初期値**（データから作る目安。利用者が見て調整する出発点）:
  - 観測雑音 σ は隣り合う値の差の中央絶対偏差から推定する（σ ≈ 1.4826·MAD/√2）。ゆっくり変わる信号成分と
    外れ値の影響を受けにくいため。
  - プロセス雑音 q は、フィルタの帯域 ω がサンプリング周波数の 1/20 になるよう q = ω⁴σ²Δt とする。
  - 初期共分散は、先頭の状態が σ²、k 階微分が (信号の広がり × ω^k)²。初期状態は最初の観測
    （多項式の観測モデルでは 1 次の項で逆算した値）。カットオフ周波数は min(10 Hz, fs/10)。
  - 雑音・共分散は有効数字 4 桁に丸めて入れる（打ち直しやすさのため）。初期状態は丸めない。オフセットの
    大きな信号では、丸めの誤差が σ を超えて初期の推定を誤らせるため。
- **数値の表示**: 入力欄と行列の表は、読み戻すと同じ値になる最短の表記で表示する。当初は有効数字 10 桁で
  表示していたが、保存した解析を読み込んで再計算するだけで、表示の丸めにより条件とキャッシュの指紋が
  変わってしまうため改めた。
- **縦並べの連動規則の変更**: Phase 2 の規則（基準パネルと比較できないパネルは連動させない）では、
  低レート側のパネルどうし（カルマンフィルタの推定値・微分・√R）も連動せず、一緒にズームできなかった。
  同じ時間軸のパネルどうしは、その時間軸で一番上のパネルに連動させるよう変えた。警告は「基準パネルと
  比較できない」ことだけを 1 行で示し、詳しい説明はツールチップに出す（プロットの高さを削らないため）。
- **結果の置き場所**:
  - 初めて結果を出す解析は、推定値（処理結果）を入力チャンネルと同じパネルに重ねる。カルマンフィルタの
    追加の出力（微分・イノベーション・√R）は、解析パネルで選んだものだけ新しいパネルに置く。
  - 新しいパネルを足しても、選択中のパネル（ツリーから追加する系列の行き先）は元に戻す。
  - 入力を表示していなければ、空の選択中パネル（なければ新しいパネル）に入力と結果を並べる。
  - 再計算した結果は、表示中の系列をその場で描き直す（色と並び順を保つ）。
- **表示設定の形式 v2**: パネルの `channel_ids` を `series_ids` に改名した（解析の出力も置けるため）。
  v1（形式バージョンを書いていない最初期のファイルを含む）は読み込むときに変換する。
- **取り込みダイアログの事前確認**: 「取り込む」を押すと、ファイル全体を指定どおりに検証する
  （書き込みはしない。`DataImporter.check`）。プレビュー（先頭 20 行）では分からない異常を確定前に見せるため。
  エラーがあれば閉じない（警告を確認した後にファイルが変わった場合も同じ）。警告だけなら一度表示し、
  同じ指定でもう一度押したら取り込む。指定を変えたら確認し直す。
- **保存した解析の読み込みの失敗**: 壊れた・新しい形式・開けない解析ファイルは飛ばしてメッセージで知らせ、
  他の解析は使えるようにする（1 つのファイルのためにプロジェクト全体を開けなくしない）。
- **構成**: 解析の種類ごとの分岐・出力の情報・キャッシュとの変換・GUI の初期値は `analysis/runner.py`
  （Qt に依存しない）に置いた。GUI は、条件を編集する `ui/analysis_panel.py` と、実行・表示・保存の流れの
  `ui/analysis_controller.py` に分けた。メイン画面に入れると、取り込み・ツリー・解析が 1 つのクラスに
  集まって追いにくくなるため。
- **PyQtGraph の注意**: 表示範囲の切り出し（`setClipToView`）は、線をプロットに追加した後に設定する
  （追加前に設定すると AttributeError になる）。帯は FillBetweenItem、印は ScatterPlotItem で描く。

## 2026-11-05 — Phase 4: 入出力関係の解析の設計
- **仮定（ユーザーに確認待ち、SPEC §13）**: 応答を調べる実験の形（ステップ状か連続的か）は未回答なので、
  両方に対応した。ステップ状の入力にはステップ応答の指標、連続的に変化する入力には相互相関を使う。
- **解析の位置付け**: 2 チャンネルの解析も `AnalysisSpec` に統合した（`output_channel_id`・`alignment` と
  種類ごとの条件を追加。形式は v2 で、v1 のファイルはそのまま読める）。保存・ツリー・調整・削除・
  ワーカースレッドでの実行の流れをそのまま使えるため。代替案は別のモデルと保存先を作ることだが、
  同じ処理を 2 通り持つことになり、Phase 5 の解析でも増え続ける。
- **結果の形**: `AnalysisResult` に、指標（`metrics`）・グラフ（`charts`）・時刻の印（`time_markers`）を加えた。
  表示側は解析の種類を知らなくてよいので、Phase 5 の周波数解析も同じ部品で表示できる（対数軸の指定も入れた）。
  2 チャンネルの解析は時系列を出力せず、計算が速いのでキャッシュもしない（開くたびに計算する）。
- **時刻の対応付け（A-11）**: `ChannelAligner` に集めた。
  - 時計が違うチャンネルは、時刻オフセットを明示しなければ対応付けない。オフセットは解析の条件として保存する。
  - 補間は重なる範囲の中だけで行い、外挿しない。間隔が中央値の 1.5 倍を超える区間（欠損）はまたがず NaN にする。
    取り込み時の「時刻の飛び」と同じ基準。不規則な時刻のデータでは `max_gap_factor` を大きくする。
  - 時刻が同じ 2 チャンネルは補間しない。行ったことは `AlignmentRecord` に残して結果に表示する。
  - 宣言したオフセットは、その解析の中だけで使う。縦並べの時間軸の連動には影響させない。
    プロジェクト全体の時計の対応（時計グループ）は、同期を扱う Phase 7 で検討する。解析の条件を変えただけで
    他の表示の時間軸が動くと、何を見ているか分からなくなるため。
  - 相互相関で求めた遅れを、時刻オフセットとして自動で使うことはしない（SPEC の v0.3 も「提案」まで）。
- **相互相関（A-09）**: 遅れごとに重なっている部分のエネルギーで正規化する。全体の長さで割る一般的な方法は、
  なだらかなピークの位置が 0 の側にずれる（3 秒のデータで約 3 ms と見積もった）。相関の絶対値が最大の遅れを選び
  （出力が逆向きでも見つかる）、3 点の放物線でサンプル間隔より細かく求める。重なりが半分未満の遅れは探さない。
  真の遅れが探索範囲の外だと範囲の端が最大になるので、そのことを注記する。
- **ステップ応答（A-09）**: 範囲の先頭と末尾の平均を初期値・最終値にする。
  - 指標は応答開始の遅れ・Td（50%）・Tr（10〜90%）・τ と L（2 点法）・Ts・オーバーシュート。
    「遅れ時間」の定義が文献で分かれるので、しきい値で見た遅れと 50% の遅れの両方を出す。
  - τ と L は Smith の 2 点法（28.3% と 63.2%）。一次遅れ＋むだ時間の応答なら厳密に求まる。
  - しきい値を越えた時刻は、応答が 50% に達した点を基準に探す。単純に最初の越えを取ると、
    雑音の一瞬の越えを変化の開始と取り違えるため。
  - 変化したかどうかの判定には、隣り合う値の差から求めた雑音を使う。標準偏差を使うと、平均の区間に
    ステップが紛れ込んだときに「変化が区別できない」という誤った説明になった（テストで検出）。
  - 入力のステップはサンプルの間で起こるので、変化の開始は 1 サンプル以内の精度で決まる。
  - 求められない指標は None にして理由を注記する。範囲は 1 回の変化を含むように利用者が選ぶ。
- **ヒステリシス（A-10）**: 分岐は入力の変化の向きで判定する。
  - 向きの判定にだけ平滑化を使い、X-Y の値と指標には平滑化しない値を使う。
  - 遅いサンプルを除く基準は |du/dt| の 95 パーセンタイル（最大値は雑音に左右される）。
  - 分岐の値は、区間ごとに直線を当てはめて区間の中央の値を求める。当初の単純な平均では、2 つの分岐の
    サンプルの位置のずれが差として現れ、ヒステリシスのない特性でも FS の約 0.03% の差が出た（テストで検出）。
  - FS は回帰直線の上の出力の変化。遊びのある特性では、回帰直線の傾きは真の倍率より少し小さくなる。
  - 応答の遅れがあるとループが開くので、測った値には静的なヒステリシスと遅れの分が含まれる。
    分けるには入力をゆっくり変えるか、遅れの分を計算して引く。
- **合成データ**: `io_pair.csv` を試技ごとに追加した。真値（むだ時間・時定数・遊びの幅など）は目録の `io_system`。
  前半はステップ、後半は三角波。乱数は既存のファイルの後で使うので、既存のファイルの内容は変わらない。

## 2026-11-05 — 使い方の流れの作り直し（ユーザーの意見「そもそも全然扱いづらいし、UIとして全然分かりづらい」）
見た目を直しても評価が変わらなかったので、最初に通る流れを実際にたどって原因を調べた。それまでの確認は、スクリプトで
取り込みと解析を済ませた後の画面だけで、新規作成・取り込みダイアログ・空のプロジェクトを一度も見ていなかった。
原因は細部ではなく構造で、**データを見るツールではなく、データを管理するツールの形になっていた**
（CSV を 1 つフィルタにかけるまでに、プロジェクト名・保存先・13 項目のダイアログ・ダブルクリックが必要で、
取り込んでもグラフには何も出なかった）。ユーザーが選択肢から選んだ方針は「ファイルを開くだけ」「左で選び右で調整」。

- **ファイルを開くだけで始める（SPEC F-01 の変更。ユーザー承認済み）**: 保存先は自動で用意する。名前は
  `<ファイル名>_<内容の SHA-256 の先頭 12 文字>` で、利用者のデータのフォルダ（Windows では
  `%LOCALAPPDATA%\ExperimentWorkbench\workspaces`）に作る。
  - 内容のハッシュを使うので、同じ内容のファイルを開くと同じ保存先になり前回の続きから始まる。別の対応表を持たなくて
    済み、ファイルが変わっていれば別の保存先になって前の結果と混ざらない。
  - 代替案: データファイルの隣に作る → データのフォルダが散らかり、読み取り専用の場所やネットワーク上のファイルを
    開けない。開くたびに新しく作る → 続きから始められず、ディスクも増える。
  - 影響: 保存先が増え続けても自動では消さない（元ファイルのコピーが残るので容量を使う）。自動の掃除は未実装。
    保存先を指定するプロジェクトは「保存先を指定して始める」として残し、既存のプロジェクトも開ける。
- **読み方は中身から判定し、判定できないときだけ尋ねる**: `DataImporter.suggest()` が文字コード（UTF-8 → cp932）、
  区切り文字と前置きの行数（区切り文字の数が揃う行を探す）、時刻列（列名）、時刻の単位（列名）、チャンネルの単位
  （列名の括弧）を決める。Qt に依存しない。
  - 推測で取り込まない: 時刻列が名前から分からない、数値の列がない、構造にエラーがあるときは確認の画面を出す。
    最初の列を時刻とみなす案は、値の列を時刻と誤読しても気づけないので採らなかった。
  - 単位が列名から分からない時刻列は秒として読むが、誤ると時間軸が丸ごとずれるので、必ず警告で知らせる
    （ここだけは確認の画面を出さない。`time` という列名はよくあり、毎回尋ねると「開くだけ」にならないため）。
  - データの異常の警告（時刻の飛びなど）は、確認の画面を止めずにメッセージの欄を開いて見せる。隠してはいない
    （SPEC 原則 6）。エラーは従来どおり取り込まず、理由を添えて確認の画面を出す。
- **2 つ目のファイルでは時計だけを尋ねる**: 同じ時計かどうかは結果の解釈を左右し、推測してはいけない（CLAUDE.md 原則 5）。
  これまでは取り込みダイアログの小さなチェックボックスだったので、追加のときの独立した質問にした。既定の答えは
  置かない。最初のファイルは同じ時計として登録する（比べる相手がいないので害がなく、2 つ目で「同じ時計」と
  答えたときに連動できるようにするため）。
- **データの一覧**: 実験・セッション・試技の階層は画面に出さず、ファイル → チャンネル → 処理の順に並べる。
  データモデルと保存の形式は変えていない（SPEC の比較機能で使う）。複数の試技があるプロジェクトでは、ファイル名の
  前に試技名を付ける。表示はチェックで切り替え、クリックは処理の対象の選択だけにした。クリックとダブルクリックで
  意味が変わるのは見ても分からなかったため。チェックとグラフの表示は常に一致させる。
- **処理の選び方**: プルダウンをやめて、処理の一覧のボタンにした。画面は「処理の一覧」と「条件の調整」の 2 つに分けた。
  ボタンを押すと新しい処理になり、すぐ計算する。KF・EKF・AKF はモデルと適応推定の組み合わせだったのを、
  それぞれのボタンにした。主要な数値にはスライダーを付けた（桁で効くので対数の目盛り。欄が値の持ち主で、正確な値は
  打てる）。
- **実行と保存のボタンをなくした**: 条件を変えると計算し、計算できたら自動で保存する。「実行」「保存」「新しい解析として
  保存」「変更したら自動で再計算」はなくなった。比べたいときは「複製して比べる」で処理を増やす。計算できなかった
  条件は保存しない。保存のたびに一覧を作り直すと選択が動くので、処理が増えたときと出力の構成が変わったときだけ
  作り直し、それ以外は行の名前だけを更新する。名前には条件を入れる（`accel LPF 10 Hz`）。凡例で見分けるため。
- **カルマンフィルタの追加の出力**: 「新しいパネルに出す結果」の設定をやめた。推定値だけを入力に重ね、微分などは
  一覧のチェックで出す。
- **グラフの操作**: 左ドラッグを移動から「選んだ範囲の拡大」に変え、ダブルクリックで全体に戻す。時系列のビューアでは
  範囲を選んで拡大する操作が主で、移動より頻度が高いため。移動はスクロールバーと右ドラッグ。操作の案内を
  ステータスバーに常に出す。ドラッグの処理は `ViewBox.mouseDragEvent` を差し替えている（クラスは継承しない方針のまま。
  カーソルや範囲の端のドラッグは、それらの部品が先に受ける）。
- **パネルは表示に合わせて増減する**: 「パネルを追加」の帯と「選択中のパネル」の青い枠をやめた。チェックで新しいパネルが
  増え、空になったパネルは閉じる。重ねたいときはパネルへドラッグする。パネルが多いときは高さを保ってスクロールする。
- **下の欄は普段隠す**: 解析結果は 2 チャンネルの解析のときだけ、メッセージは警告とエラーのときだけ出す。

- ドラッグとダブルクリックは、PyQtGraph との連携を確かめるため、模擬オブジェクトではなく実際のマウスのイベントで確かめる。

## 2026-11-05 — 図が自分で説明する形にする（ユーザーの意見「各図の意味がものすごく分かりづらくて、何をしているのかが直感的に全く伝わらない」）
図は数値を並べるだけで、説明していなかった。パネルの見出しは `high_rate / accel 4.6919` のように説明のない数値で、
処理の結果は同じ強さの線で元の線に重なり、2 チャンネルの解析は用語の表と記号が中心で、結論がどこにも書かれていなかった。
どの図でも、**何の図か・どの線が何か・何が起きたか・何をしているのか**が見れば分かることを方針にした。

- **説明のない数値を出さない**: 各パネルの `t = 28.694 s` と値は、カーソルを既定で出していたために常に見えていた。
  カーソルはクリックして読もうとしたときだけ出す。
- **パネルの見出し**: チャンネル名と単位にした。ファイル名は 2 つ以上のファイルを並べたときだけ添える。
- **処理の前後を見分ける**: 結果を重ねると、元の線を「元データ」としてグレーで後ろに退かせ、結果は条件だけの名前
  （`LPF 10 Hz`）にする。比べる結果がなくなれば元の色に戻す。
- **取り除いた成分を見られるようにする**: フィルタの結果の線だけでは、何が取り除かれたかが分からない。信号に比べて
  雑音が小さいと、全体表示では前後の差がほとんど見えないため。フィルタの出力に `removed`（元 − 結果）を加え、
  一覧のチェックで入力のすぐ下に出す。微分・積分は単位が変わるので出さない。
- **単位が違う結果は重ねない**（不具合の修正）: 微分を元の線に重ねると、縦軸が微分の大きさに合わせられて元の線が
  読めなくなっていた。入力と同じ量の結果だけを重ね（`overlays_input`）、それ以外は入力のすぐ下のパネルに置く。
  EKF の多項式の観測で式が恒等でないとき、線形モデルで観測が先頭の状態そのものでないときも、別の量なので重ねない。
- **結論を文で書く**: `AnalysisResult.headline` に、数値入りの一文を入れる。例: 「出力は入力の変化から 9.37 ms 遅れて
  動き始め、23 ms で変化の半分に達し、75.2 ms で落ち着きました。」文は解析コアで作る（Qt に依存せず、テストできる）。
  判定の言葉は足さない（「良い」「小さい」などの評価は研究の文脈によるため）。
- **グラフ自体に説明を書く**: 題名を普通の言葉にし、図の中に書く。縦線と文字の注記（`ChartAnnotation`）で、凡例と別の表を
  見比べなくても読めるようにした。凡例は読み取る線だけにした（`ChartSeries.show_in_legend`）。
  ステップ応答は変化前 0 %・変化後 100 % に揃え、短い時間は ms で表す。ヒステリシスは差が線の間隔としては小さいことが
  多いので、差そのもののグラフも加えた。
- **時刻の印は番号にする**: 近い時刻の印の名前は重なって読めなかった。縦並べ表示には ①〜④ だけを出し、意味は結果の
  グラフの注記で示す。青い帯には「解析する範囲」と書く。
- **処理の説明**: 調整の画面の先頭に、何をする処理か、条件を動かすとどうなるかを書く。処理の一覧にも見出しごとの説明を
  付けた（これまではマウスを置かないと出なかった）。
- **結果の欄を整理した**: 補間や時刻オフセットなど結果に関わる変換は `summary` で必ず見せ、同じ時刻をそのまま使ったときの
  定型の記述と範囲は `conditions` として畳む。何も変換していないのに「補間: なし…」が表を圧迫していたため。
  更新しなかった時刻も 0 個なら書かない。
- 代替案: 結果の欄に用語の解説を増やす案は採らなかった。文章を読まないと図が読めない状態が、変わらないため。

### ヒステリシスの不具合（Phase 4 から）
結論の文を見直していて、既定の条件のヒステリシスが真値の約 1/7 になっていることが分かった。入力の雑音は標準偏差 0.02 と
小さいが、向きの判定に使う du/dt では雑音が実際の変化の速さの約 10 倍になり、増加時と減少時のサンプルが混ざって差が
打ち消し合っていた。Phase 4 の検証は、デモのスクリプトで平滑化をオンにしていたので見つからなかった。

| 条件（合成データ、真値 0.3137） | 最大ヒステリシス |
|---|---|
| 平滑化なし（修正前の GUI の既定） | 0.0458 |
| カットオフ 50 Hz | 0.3065 |
| カットオフ 0.5〜20 Hz | 0.3165 |

- GUI の既定を平滑化ありにし、カットオフの初期値をサンプリング周波数の 1/200 にした（1 kHz なら 5 Hz）。平滑化が強すぎても
  傾きの符号は保たれやすく、上の表のとおり広い範囲で結果が変わらないため。
- 向きの判定が乱れている（向きが反転するサンプルが 5 % を超える）ときは `direction_unstable` を立て、注記に加えて
  結論の文で注意する。条件を変えても、誤った数値が黙って結論として出ないようにするため。
- `HysteresisParams.smoothing_cutoff_hz` の既定の None（平滑化なし）は変えていない。スクリプトから使うときの意味を変えない
  ためで、平滑化なしでも上の判定で注意が出る。
- 保存済みの処理は保存した条件のまま開く。平滑化なしで保存されたものには、結論の文の注意が出る。

## 2026-11-06 — パラメータの用語と、値の変換・時間の処理・統計（ユーザーの意見「細かい計算するためのパラメータ設定時のUIや言葉の使い方が正しければ」「他のデータ処理も可能にしておきたい」）

### 用語
前回（図が自分で説明する形にする）で平易な言い換えを入れたが、研究の計算条件を決める画面では、言い換えがかえって定義を
あいまいにする。論文や教科書の用語と対応しないと、値の意味を確かめられないため。

- 方針: **ラベルは標準の技術用語、平易な説明は説明文とツールチップに置く。** 前回の言い換えの一部は取り消した。

| 以前の表示 | 今の表示 |
|---|---|
| 元データ | 生データ |
| 取り除いた成分 | 除去成分 |
| ノイズ | 雑音 |
| 増やすとき / 減らすとき | 増加時 / 減少時 |
| 動き始め | 応答開始遅れ |
| 落ち着く | 整定時間 Ts |
| 範囲を指定 | 解析範囲を指定 |
| 平滑化してから求める | 解析の前にローパスフィルタをかける |

- 指標は定義の決まった記号と併記する: 遅れ時間 Td、立ち上がり時間 Tr、時定数 τ、むだ時間 L、整定時間 Ts、定常ゲイン。
- カルマンフィルタは プロセス雑音 PSD q、観測雑音の標準偏差 σ、プロセス雑音共分散 Q、観測雑音共分散 R、状態遷移行列 F、
  観測行列 H、初期状態 x₀、初期誤差共分散 P₀ と書く。q の単位は入力の単位と微分の階数から表示する
  （単位²/s^(2d+1)。Q₀₀ = qΔt^(2d+1)/… から導いた）。
- 代替案: 用語と平易な語を両方ラベルに書く案は、狭いパネルで欄が読めなくなるので採らなかった。

### 新しい処理
- `analysis/transforms.py` に集めた（値の変換・時間の処理・区間統計は、どれも 1 チャンネルを受けて結果を返す同じ形なので、
  細かく分けない）。条件は `AnalysisSpec` の同名の項目で保存し、解析の形式バージョンは 3 に上げた。
- 値の変換は NaN を残す。埋めるのは「欠損の補間」だけで、埋めた時刻は × 印で示す（黙って修正しないため）。
- 切り出しは時刻を元の時間軸のまま保つ。他のチャンネルと並べて比べられなくなるのを避けるため。原点を 0 にする処理は作らない。
- リサンプリングで周波数を下げるときは、既定でアンチエイリアスフィルタ（0.4 × 変換後の周波数、8 次、ゼロ位相）をかける。
  かけられないとき（NaN や不等間隔があるとき）は、折り返しの可能性を注記に出す。
- 値の単位が同じ結果だけを生データに重ね、単位や桁が変わる結果（線形変換・正規化・オフセット除去など）は入力のすぐ下の
  パネルに出す。重ねると縦軸が片方に合わせられて、もう一方が読めなくなるため。
- 代替案: 処理の結果を次の処理の入力にする連結は今回は入れなかった。派生データの依存関係を保存・再計算する仕組みが必要で、
  §7 v0.2 のパイプラインの範囲のため。

### 実際の画面で見つけて直したこと
- **欠損の補間:** 行ごと欠けた区間があるデータで「欠損はありません」と出ていた。NaN がないので文としては正しいが、データが
  欠けているのに「ない」と読める。`GapFillResult` に時刻の飛びの数と長さを持たせ、「NaN の欠損はありません」と書いたうえで
  飛びと埋める方法（リサンプリングの倍率）を結論の文に併記する。判定の基準は読み込みの警告と揃え、定数を
  `DEFAULT_MAX_GAP_FACTOR` にまとめた。
- **指標の書き方:** 単位の文字列「時刻 s」で時刻を表していたので、`AnalysisMetric.display`（物理量・時刻・個数）に分けた。
  長さとしての時間は 1 秒未満をミリ秒で書くが、時刻はグラフの目盛りと見比べるので秒のまま書く。個数は指数表記にしない。
- **EKF の係数表:** 列の幅が固定で、横スクロールバーが唯一の行を隠していた。列を幅に合わせて広げ、スクロールバーが出るときは
  その分だけ高くする。見出しも式の添字と同じ c0, c1, … にした。
- **ヒストグラム:** 折れ線で描いていたので棒にした（`ChartStyle.BARS`）。棒の幅は階級の幅で、隙間を空けない。
- **解析範囲の初期値:** 範囲の欄を埋める仮の値 0〜1 が、時刻 0 から始まるデータでは「選ばれた範囲」として扱われ、切り出しや
  ステップ応答が先頭の 1 秒から始まっていた。確認に使ったデータの時刻が 30 s 付近から始まっていたので、既定の条件での検算まで
  気づかなかった。範囲は選ばれるまで「未選択」とし、未選択ならデータの中央の 4 割から始める。

### テストの範囲（ユーザーの意見「こんなにテスト必要？いらない気がしている」）
- 自動テストは、計算結果の正しさ、元データの保護、実際に起きた不具合の再発防止に絞る。CLAUDE.md の「妥当な自動テスト」は
  この意味で解釈する。文言・書式・レイアウトだけのテストは書かず、表示は画面を描いて確かめる。
- 理由: 上の問題はどれもテストではなく、画面の確認と既定の条件での検算で見つかった。表示のテストは、用語を見直すたびに
  直す手間を増やしていた。
- 既存のテストは消さない。この基準に合わない候補（108 関数）を洗い出したが、利用者の判断でそのまま残す。基準は新しく書く
  テストに適用する。
