# Experiment Workbench — 開発設計書 v0.1

- ステータス: Phase 0〜4 完了（解析コア、取り込みから縦並べ表示、GUI 上での解析と調整、入出力関係の解析）と、使い方の流れの作り直し（2026-11-05）/ 次は Phase 5（周波数解析）
- 開発手段: Claude Code
- 対象: Windows 11 / Ubuntu デスクトップ
- 言語: Python（第一段階）
- 目的: 実験の時系列データを**読み込む・理解する・同期する・処理する・比較する・再現する**ための汎用デスクトップツール
- 第一の検証データ: IMU（約1000 Hz）、MoCap（約100 Hz）、4ch圧力センサ。ただしUI・データモデルは特定センサに依存させない。
  （2026-10-29 追記: 合成データはセンサ非依存の汎用データとした。詳細は §10 と `docs/DECISIONS.md`）

## 1. プロダクトの位置付け

単なるCSVグラフ表示ツールを作るのではなく、**解析手順を保存し、別の試技や新しいデータに再適用できる研究用ワークベンチ**とする。

既存のPlotJugglerには時系列表示・信号変換・複数試技の重ね合わせ・レイアウト保存など高度な機能が既にある。したがって、自作の独自価値は以下に置く。

1. 実験（experiment）・セッション（session）・試技（trial）・データソース（source）を体系的に管理する。
2. 異なる時間基準・サンプリング周波数の信号を明示的に同期・比較する。
3. 前処理パイプラインをパラメータ付きで保存し、複数試技に一括適用する。
4. 生データ、導出データ、グラフ、計算条件を追跡可能にする。
5. Pythonで新しい解析アルゴリズムとデータ読み込み形式を拡張できるようにする。

**非目標**: DAQ装置の制御、常時リアルタイム計測、動画・3Dモーションの完全統合、研究領域固有の自動解析、LLM分析、論文の自動作成（少なくともv0.1では対象外）。

## 2. 想定ユーザーと代表ユースケース

- 複数のセンサログをインポートし、同じ画面で表示する。
- IMUとMoCapで別々の時刻原点・周波数が存在しても、イベント時刻を基準に比較する。
- 別の試技に同じフィルタ・補正・積分処理を再実行する。
- 複数の成功／失敗試技を重ね描きし、ピーク値、RMSE、相関などを比較する。
- 解析条件と図表を保存し、時間が経っても結果を再生成できる。

## 3. 基本思想・設計原則

1. **非破壊**: 生データは更新しない。変換は派生データとして保持する。
2. **明示的な時刻定義**: サンプル番号、相対秒、絶対時刻、イベント相対時刻を区別する。
3. **計算と表示を分離**: 描画用間引き結果を解析計算に流用しない。
4. **再現性**: 元データのハッシュ、処理パラメータ、処理コード／ツールのバージョン、依存関係を記録する。
5. **段階的拡張**: センサ固有のパーサーや解析処理はプラグイン化可能な境界を確保するが、v0.1では過度なプラグイン基盤を作らない。
6. **失敗を隠さない**: 読み込み失敗、時刻重複、欠損、単位不一致、外挿はUIに明示する。
7. **オフライン優先**: LLM・クラウド接続を必須としない。

## 4. 技術スタック（初期決定）

| レイヤー | 採用候補 | 理由 |
|---|---|---|
| デスクトップGUI | PySide6 | Windows / Ubuntu対応。Pythonの数値処理との接続が単純 |
| 高速時系列プロット | PyQtGraph | 大規模な時系列をインタラクティブに操作しやすい。表示用downsampleが可能 |
| データ処理 | NumPy / SciPy | 信号処理・統計処理の標準的基盤 |
| ウェーブレット解析 | PyWavelets | SciPy の連続ウェーブレット変換は削除済みのため（2026-10-29 追記。周波数解析の Phase で導入） |
| データ読み込み・変換 | Polars | CSV/Parquet、遅延読み込み、列選択に適する |
| データ永続化 | Parquet + SQLite | 数値列とメタデータを分離して保持 |
| 設定・型検証 | Pydantic | インポート設定、解析手順、プロジェクト構造の検証 |
| テスト・品質 | pytest / Ruff / mypy | Claude Codeによる改修で品質を維持 |
| 配布 | 最初は `uv` で起動、後にPyInstaller等を評価 | 初期は実装と検証を優先 |

PySide6 / PyQtGraphを第一候補とする。Tauri + TypeScriptは代替候補だが、v0.1時点ではPythonとのプロセス間連携の複雑さを増やさない方針。ライセンス確認はリリース時に実施する。

## 5. データモデル

### 5.1 階層

- **Project**: 研究またはデータ解析プロジェクト
- **Experiment**: 目的・実験条件を共有する試験群
- **Session**: 収録日や装置設定など共通条件のまとまり
- **Trial**: 1回の試行。成功／失敗などのタグを持てる
- **Source**: 1つの入力ファイルまたはストリーム由来のデータ群
- **Channel**: 個別の時系列（値、単位、時間軸、サンプルレートなど）
- **Event**: 任意の時刻・ラベル・検出方法を持つイベント
- **Pipeline**: 変換ノード、処理順序、パラメータ、入出力チャンネルの定義
- **View**: 表示するチャンネル、軸範囲、色、配置、同期条件を保存したもの

### 5.2 タイムスタンプ

各Sourceは独立した時間軸を持てる。内部的に時刻は秒単位のfloat64を基本とし、絶対時刻が必要ならepoch nanosecondsの整数列を併用する。時刻の精度・原点・装置クロックの由来をメタデータとして保持する。別Source間のオフセット・ドリフト補正は**明示的な変換**として記録する。

サンプリング周波数は推定値を含めてメタデータとし、各サンプルの実時刻がある場合はそれを優先。異なるサンプリングレートを無断で揃えない。単位系は原則SI、元の単位も保持する。

### 5.3 保存構造（案）

```text
my-experiment/
├── project.json           # プロジェクトの基本情報とスキーマバージョン
├── metadata.sqlite        # 実験/試技/チャンネル/イベント/処理履歴
├── originals/             # インポートした元データ（コピーを選択した場合）
├── datasets/              # 正規化データ（Parquet）
├── derived/               # 処理結果のキャッシュ（Parquet）
├── pipelines/             # 処理定義（JSON）
├── views/                 # 表示設定（JSON）
└── exports/               # CSV、画像等
```

インポート元を参照する方式も将来対応しうるが、v0.1では元データをプロジェクトにコピーし、SHA-256を記録する方式を基本とする。プロジェクトの移動・再オープンでパスが壊れないことを重視する。

### 6.2 基本操作

- CSV/TSV/Parquetをドラッグ＆ドロップで読み込む。
- インポート時に時刻列・単位・ヘッダー・区切り文字・試技を指定できる。
- 左のツリーからチャンネルをプロットへ追加する。
- ズーム、パン、カーソルによる時刻・値の確認、複数プロット間のX軸同期を行う。
- イベント時刻を手動で登録し、`t=0` として複数試技を整列する。
- ビュー設定を保存して再オープンできる。
- （2026-10-29 追記）複数のパネルを縦に並べ、時間軸を連動させて、生データ・処理結果・異なる量を見比べる。
- （2026-10-29 追記）解析条件（フィルタの条件、カルマンフィルタの行列など）を GUI 上で数値として編集し、
  結果をすぐ見比べながら調整する。今後の解析は「GUI 上で見て、判断して、調整する」流れを前提とする。
- （2026-10-29 追記）加速度などの信号の周波数成分を、スペクトル・スペクトログラム・ウェーブレットで確認する。
  時間周波数の表示は、縦並べパネルと時間軸を連動させる。
- （2026-10-29 追記、Phase 3）§6.1 の右側（Properties）は、解析パネル（ツリーで選んだチャンネルを入力に、
  解析の種類と条件を数値で編集し、実行・中止・保存する）として実装した。
- （2026-11-05 追記）画面の下は、解析結果（指標の表と X-Y などのグラフ）とメッセージのタブにした。
  左右のパネルは上下いっぱいに使う。チャンネルはパネルへドラッグでき、ファイルはウィンドウへドラッグして
  取り込める。解析する範囲はグラフの上の青い帯をドラッグして選べる。
- （2026-11-05 追記、ユーザー承認済み）**ファイルを開くだけで使い始められること**を基本の流れとする。
  1. ファイルをドロップするか開くと、確認なしで全チャンネルをグラフに表示する。読み方は中身から判定し、
     判定できないときだけ確認を求める。保存先は自動で用意し、同じ内容のファイルを開くと続きから始まる。
  2. 左の一覧はファイル → チャンネル → 処理の順に並べ、チェックで表示を切り替える。実験・セッション・試技の階層は
     画面に出さない（§5 のデータモデルは変えない）。
  3. 右で処理のボタンを選ぶと結果が元の線に重なり、スライダーや数値を変えるとその場で更新される。保存は自動。
  4. 2 つ目のファイルを開くときは、同じ時計で記録したかを尋ねる（時計の違いは推測しない）。
  5. グラフは左ドラッグで範囲を拡大、ダブルクリックで全体、スクロールバーと右ドラッグで移動する。
  6. 下の欄は、解析結果や警告があるときだけ出す。

### 解析コア（2026-10-29 追記。A-01〜A-08 は GUI より先に実装済み、A-09〜A-14 の時期は §11）

与えられた任意の時系列（時刻配列と値の配列）に対して、GUI に依存せずに使える解析処理。
パラメータは pydantic モデルとして保存できる形にし、v0.2 の処理ノード・パイプラインの部品にする。

| ID | 機能 | 受入条件 |
|---|---|---|
| A-01 | 入力検証 | 時刻の逆行・重複・非有限値、値の NaN、等間隔を前提とする処理での不等間隔（欠損による時刻の飛びを含む）を、黙って修正せず説明付きのエラーにする |
| A-02 | フィルタ | バターワース（LPF / HPF / BPF / BSF、ゼロ位相または因果的）、移動平均（中心または後方）、Savitzky-Golay 平滑化。端点の扱いと位相特性をパラメータとして記録する |
| A-03 | 微分 | 中心差分（不等間隔に対応）と Savitzky-Golay 微分。1 階・2 階 |
| A-04 | 積分 | 累積台形則・累積シンプソン則（不等間隔に対応）。初期値を明示する |
| A-05 | カルマンフィルタ（KF） | 線形状態空間モデル（定数行列）と、時刻間隔に応じた運動学モデル（値とその時間微分を状態とする）。観測が NaN の時刻は予測のみ行う |
| A-06 | 拡張カルマンフィルタ（EKF） | 非線形の状態遷移・観測関数とヤコビアンを Python API で与えて推定できる |
| A-07 | 適応カルマンフィルタ（AKF） | 観測雑音共分散 R をイノベーションから逐次推定する（窓付きイノベーション推定、Sage-Husa 推定）。推定値の正定値化を行った時刻を結果に記録する |
| A-08 | 結果の記録 | カルマンフィルタ系は状態・共分散・イノベーション・使用した R・観測更新の有無を時刻ごとに返す |
| A-09 | 応答・遅れの解析 | 入力と出力の 2 チャンネル（例: 張力と電圧）について、相互相関による遅れの推定（探索範囲を指定、サブサンプル精度）と、入力の変化の開始（しきい値で検出し、条件を記録）を基準にした出力の応答指標（遅れ時間・10〜90% 立ち上がり時間・時定数・整定時間・オーバーシュート）を求められる |
| A-10 | ヒステリシス・入出力特性 | 入力に対する出力の関係から、回帰直線（感度・オフセット）と直線性誤差、入力の増加時と減少時の分岐の差（最大ヒステリシスとそのフルスケール比）、ループ面積を求められる。分岐の判定条件（入力の変化方向、平滑化の条件）を記録する |
| A-11 | 時刻の対応付け | 異なる Source のチャンネルを同じ時間軸で扱う前に、時刻の対応（同じ時計で記録した、または時刻オフセット）を明示する。サンプルごとの比較が必要な解析では、指定した時間軸への補間（方法・範囲を指定、外挿しない）を明示的な変換として行い、条件を記録する。同じ Source の列は変換なしで対応付ける |
| A-12 | スペクトル解析 | FFT による振幅スペクトル、Welch 法によるパワースペクトル密度、短時間フーリエ変換によるスペクトログラムを求められる。窓関数・区間長・重なり・トレンド除去・スケーリング（密度かパワーか）を条件として記録し、周波数分解能と単位を結果に含める。等間隔の時刻が必要 |
| A-13 | ウェーブレット解析 | 連続ウェーブレット変換による時間周波数解析（スカログラム）を求められる。ウェーブレットの種類とパラメータ、スケールと周波数の対応を記録し、端点の影響を受ける範囲（影響円錐）を結果に含める |
| A-14 | 周波数応答 | 入力と出力の 2 チャンネルのクロススペクトルから、伝達関数（ゲイン・位相）とコヒーレンスを推定できる。位相から周波数ごとの遅れを求め、A-09 の時間領域の遅れと比較できる |

各機能は、解析的に答えが分かる信号と合成データの真値に対する精度を自動テストで確認する。
A-09〜A-11 は 2026-10-29 にユーザー要望（張力が出たときの電圧の応答・遅れ、ヒステリシス）で追記した。
既知の遅れ・時定数・ヒステリシスを持つ信号で精度を確認する。
A-12〜A-14 は同日、ユーザー要望（加速度データの FFT・ウェーブレット・スペクトル解析）で追記した。
既知の周波数・振幅を持つ信号（合成データの高レート側の振動成分を含む）で精度を確認する。

## 9. 非機能要件・注意点

- **レスポンス**: 1000 Hz × 180秒 × 複数ch程度を基本的な検証データにする。画面操作が固まらないこと。具体的な速度目標は実測で決める。
- **データ整合性**: 欠損・NaN・非単調時刻・時刻重複・想定外の単位をチェックして通知する。
- **フィルタ**: 使用した方式、サンプリングレート、端点処理、位相特性を後から再現できるようにする。
- **同期**: イベント時刻の定義と算出方法を保存する。単なるX軸の描画シフトと、物理的なデータ補正を混同しない。
- **グラフ**: 間引きは描画専用。実測値のピークが隠れないようピーク保存型の表示間引きを優先する。
- **品質**: WindowsとUbuntuで起動、主要処理の結果一致、プロジェクトの移植性を確認する。
- **セキュリティ**: 外部ファイルを取り込むためパス検証を実施。任意Python実行はv0.1に含めない。

## 10. 初期検証用データ（合成データでよい）

1. IMU: 1000 Hz、加速度3軸・角速度3軸、180秒。
2. MoCap: 100 Hz、位置3軸、180秒。
3. 圧力: 1000 Hz、4ch、180秒。
4. 複数Trial: 同様の信号にオフセット、ノイズ、欠損、異なる開始時刻を加えたもの。
5. 失敗データ: タイムスタンプ逆転、重複、空ファイル、列名重複、文字コード違い、NaNなど。

実測データは後から取り込めるようにする。個別の検出アルゴリズムの組み込みはv0.2以降に行う。

2026-10-29 追記: ユーザー判断により、合成データは 1〜3 のセンサ別データではなく、真値が解析的に分かる
1 次元の運動を周波数・時刻原点の異なる 2 ファイルで観測した汎用データとした（4・5 は満たす）。
フィルタ・積分・カルマンフィルタの結果を真値と比較できるよう、真値列（`true_` 接頭辞）を含める。
